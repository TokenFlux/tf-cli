# 还没定的：实现前需要拍板的事项

按「不定就没法写 v0 代码」的紧迫度排序。每项给建议。

---

## 必须现在定（影响 v0 的代码结构）

### A. `exec` 替换进程 还是 `fork + wait`

Unix 上 `syscall.Exec` 直接把自己替换成 harness 进程：信号、TTY、退出码全部天然正确，零转发代码。**但进程没了，退出后什么都干不了。**

| | exec 替换 | fork + wait |
|---|---|---|
| 信号 / TTY / 退出码 | 天然正确 | 要自己转发，Ctrl+C 两次的语义要处理 |
| 退出后清理临时配置文件 | **做不到** | 可以 |
| 退出后打印用量摘要 | **做不到** | 可以 |
| Windows | 无此语义，行为不统一 | 一致 |

ori 用的是「24 小时前的残留文件自动清理」——**这正是它没法保证退出时清理的证据**。

**建议 fork + wait。** 理由：退出后打印一行「本次消耗 $0.12，Claude Max 分组」是很有价值的收尾，临时文件也能确定性清理；代价只是一段一次写对就不用再碰的信号转发代码。

### B. 参数透传规则，以及 `--model` 归谁

`tkr claude --model x --resume ...` 里，哪些参数 tkr 吃掉、哪些原样传给 harness？`--model` 两边都有，是最直接的冲突。

建议规则：

1. tkr 只认**一小组自己的 flag**（`--model` `--reasoning-effort` `--profile` `--host` `--json` `--no-precheck` `--yes`），且必须紧跟在子命令之后。
2. 遇到第一个不认识的参数，**从那里开始全部原样透传**，不再解析。
3. `--` 之后无条件全部透传（逃生阀，用于传一个和 tkr 同名的 flag）。
4. **`--model` 由 tkr 吃掉**，因为要做前缀补全、拼写校验、分组解析，然后翻译成各 harness 自己的形式注入。

### C. 配置与凭据的存储形态

建议：

```
~/.tkr/config.json        0644  profile、默认模型槽、缓存策略 —— 可以分享/进工单
~/.tkr/credentials.json   0600  仅凭据，独立文件
~/.tkr/cache/             0700  目录数据、探测结果
```

- **分开存**，不要合一：config 要能贴给别人看、贴进 issue，凭据不能。
- 支持 `XDG_CONFIG_HOME` / `XDG_CACHE_HOME`。
- 系统钥匙串（Keychain / libsecret）：v0 不做，用 0600 文件；v1 作为可选后端。理由是平台差异大、SSH 无头环境反而更麻烦，而 0600 文件是所有同类工具的既有做法。

### D. 错误信息的语言

TokenFlux 的用户以中文为主，但 CLI 惯例是英文，且错误信息经常要被搜索或贴给 AI 排查。

建议：**文案跟随系统 locale，`TKR_LANG` 可覆盖；但错误码保持英文常量**（`TKR_GROUP_PROTOCOL_MISMATCH` 这类），中英文案共用同一套码。这样中文用户看得懂，搜索和贴给 AI 时又有稳定的英文锚点。

这条越早定越好——它影响之后写的每一句文案。

## 尽快定（影响 v0 体验，但不影响架构）

### E. 未登录 / harness 没装时的行为

- 未登录时 `tkr claude`：**不要直接报错**，提示「运行 `tkr login`」并且——因为 `models`/`groups` 是公开可读的——仍然可以正常展示目录类命令。
- harness 没装时：**绝不自动安装**，只打印检测到的包管理器对应的安装命令。ori 有代为安装的能力，但一个启动器擅自往用户机器上装东西是越界的，而且装错版本的锅得我们背。

### F. `--json` 的触发方式

ori 的做法是**检测到管道就自动输出 JSON**。这在 CI 里有坑：所有输出都是管道，用户可能只是想存个日志，却拿到一堆 JSON。

建议**显式 `--json`**，同时非 TTY 时把日志转到 stderr、去掉颜色和进度动画。可预测性优先于聪明。

### G. 缓存 TTL 与离线行为

- 目录数据（marketplace）：TTL 24h。启动时若过期，同步刷新但**超时 2 秒就用旧数据**，绝不因为刷新慢而卡住启动。
- 协议探测结果：TTL 短一些（1h），因为分组配置可能被管理员改动。
- 完全离线：用旧缓存 + 一行提示；无缓存时**放行**并说明预检已跳过。
- `--refresh` 强制刷新。

## 可以推迟，但要记着

### H. 自更新与安装来源识别

`tkr update` 有个真实的坑：**npm 装的和 curl 装的更新路径不同**。npm 装的自更新会和下次 `npm i` 打架。

建议启动时识别安装来源（二进制路径是否在 node_modules 下），npm 装的提示用 npm 更新，只有 curl 装的才允许 self-update。

### I. Windows 支持范围

建议 v0 出 Windows 二进制但标注实验性，只保证 macOS / Linux。要明确说出来，否则测试矩阵会失控。

### J. harness 版本兼容

claude / codex 迭代很快，注入的 flag 随时可能失效。最低限度：**记录每个 harness 已验证的版本范围，不匹配时警告而非阻断**。不做版本嗅探式的分支逻辑，那是维护地狱。

### K. 用量摘要要展示什么

依赖 A 选了 fork + wait。可选：本次消耗、命中的分组、限速窗口剩余（Key DTO 里有 `usage_5h/1d/7d` + `window_*_start`）。要定展示多少才不吵。
