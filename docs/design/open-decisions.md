# 架构与设计决策

决策记录与技术选型依据。

---

## 核心架构决策

### A. 进程替换（`exec`）与子进程管理（`fork + wait`）

Unix 上 `syscall.Exec` 直接将自身进程替换为 harness 进程，信号与退出码由系统原生接管，无需转发逻辑；但主进程退出后无法执行后续清理与状态收集。

| 维度 | exec 替换 | fork + wait |
|---|---|---|
| 信号 / TTY / 退出码 | 原生透传 | 需显式转发与终端复位 |
| 退出后清理临时配置 | 不支持 | 支持 |
| 退出后收集用量/状态 | 不支持 | 支持 |
| 跨平台行为一致性 | 平台差异大 | 一致 |

**选定方案：fork + wait。** 保障子进程退出后的确定性资源释放、终端状态复位与用量信息输出。

### B. 参数透传规则与 `--model` 归属

透传原则：

1. `tf` 仅解析内置 Flag，且要求紧跟子命令。
2. 遇到首个非内置参数时，后续参数全部原样透传至底层子进程。
3. `--` 之后的内容无条件全量透传。
4. `--model` 由 `tf` 解析并转换，处理模型补全、前缀匹配及格式适配后注入。

### C. 配置与凭据存储结构

存储规划：

- `~/.tf/config.json`（`0644`）：存储 Key 元数据、harness 绑定、默认模型槽及网关映射配置；不存在全局 current profile。
- `~/.tf/credentials.json`（`0600`）：独立存储 API Key 凭据。
- `~/.tf/cache/`（`0700`）：存储探测缓存与元数据。
- 支持 `XDG_CONFIG_HOME` 与 `XDG_CACHE_HOME` 环境变量规范。

### D. 国际化与错误输出规范

文案支持中英双语（跟随系统 Locale，支持 `TF_LANG` 覆盖）；错误码采用稳定英文常量（如 `TF_NETWORK`、`TF_NOT_LOGGED_IN`）。

## 运行时行为决策

### E. 未登录与未安装 harness 的处理

- 未登录时运行 `tf <harness>`：引导执行 `tf login`。
- 未安装对应 harness：交互模式下提供系统包管理器安装选项，非交互模式下仅打印安装指令，避免隐式越权修改环境。

### F. `--json` 触发原则

采用显式 `--json` 标志控制结构化输出，避免依赖管道隐式推断导致 CI/CD 场景输出不可预期。

### G. 缓存与探测机制

- 协议探测结果支持本地缓存，避免重复请求。
- 网络异常或离线状态支持优雅降级与缓存复用。
